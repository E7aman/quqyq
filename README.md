# Qūqyq AI — навигатор по правам и ценностям

ИИ-юрист простым языком: описываете ситуацию — получаете ответ барса-судьи **со ссылкой на первоисточник**,
пошаговый план и готовую жалобу в `.docx`. Плюс **Суд-тренажёр**: комната на 1–6 человек (вход по QR),
где ИИ-судья выслушивает стороны, задаёт вопросы и выносит учебный вердикт.

## Быстрый старт

```bash
# 1. бэкенд
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                   # впишите GEMINI_API_KEY и SECRET_KEY
python manage.py migrate                               # создаёт db.sqlite3 (аккаунты, чаты, библиотека)
# 2. фронтенд (собирается один раз, дальше Django отдаёт сборку)
cd ../frontend && npm install && npm run build
# 3. запуск (один процесс: сайт + API + WebSocket)
cd ../backend && python manage.py runserver 0.0.0.0:8000
```
Откройте http://localhost:8000. Без `GEMINI_API_KEY` приложение работает в **офлайн-режиме**:
поиск по базе и отказ «не нашёл» работают, ответы собираются из найденных фрагментов без ИИ.

Разработка фронтенда с горячей перезагрузкой: `cd frontend && npm run dev` (порт 5173, прокси на :8000).
Тесты: `cd backend && python manage.py test core` (включая полный суд по WebSocket и `core/test_everyday.py` про бытовые вопросы).
Подробный список запросов для фронтенда: `CONTRACT.md`.

### QR на телефонах
QR ведёт на `http://<адрес хоста>/?code=XXXXX`. На `localhost` телефон не зайдёт. Откройте сайт на ноутбуке
по IP в Wi-Fi (`http://192.168.x.x:8000`) или через туннель (ngrok / cloudflared), и QR автоматически будет верным.
Запускайте **один** процесс сервера: комнаты хранятся в памяти (для нескольких процессов нужен `channels_redis`).

## Архитектура

```
frontend (React + Vite + Framer Motion)         backend (Django + Channels)
  Chat.jsx   ── POST /api/chat/ ─────────────►  views.py → services.answer_chat
  Court.jsx  ── WS /ws/court/<код>/ ─────────►  consumers.py (фазы суда) → services.judge_*
  Complaint  ── /api/complaint/draft|docx/ ──►  services.draft_complaint + doc_generator.py
  Chat (фото)── POST /api/analyze/ ──────────►  services.analyze_image (Gemini vision)
                                                rag.py  (BM25 по knowledge/*.md)
                                                llm.py  (Gemini, JSON-ответы, запасная модель)
                                                security.py (очистка, антиинъекции, лимиты)
```
**Главный принцип надёжности.** Сначала RAG ищет фрагменты в `backend/knowledge/`. Если подходящих нет,
ответ «не нашёл в базе» формируется **без обращения к модели** (п. 4.9). Если есть — Gemini получает только эти
фрагменты и обязан отвечать по ним (`prompts.py`); в интерфейсе у каждого ответа карточки источников,
бейдж и шкала совпадения.

### Формат ответа чата
```json
{"refused": false,
 "panels": [{"pose": "pointing", "bubble": "реплика барса"}],
 "details": "разбор и шаги", "sources": [{"id","title","article","url","constitution","verified","quote","confidence"}],
 "disclaimer": "...", "mode": "gemini | offline | guard"}
```

### Суд (WebSocket)
Фазы: `lobby → statements → questions → verdict`. Клиент → сервер: `join`, `set_case`, `start`, `statement`,
`answer`, `force_next`. Сервер → клиент: `joined`, `state` (полное состояние комнаты), `error`.
ИИ отвечает **по ходам**, а не на каждое сообщение: это экономит лимиты Gemini. Один игрок — та же комната на одного.

## Безопасность (критерий 15 баллов)
- Ключи только в `.env` (в `.gitignore`), в код не попадают.
- Тексты очищаются и ограничиваются по длине; фильтр prompt-injection на русском/английском/казахском;
  сообщения пользователя передаются модели как данные в разделителях, а не как инструкции.
- Лимит запросов по IP (`RATE_LIMIT_PER_MIN`), лимит сообщений на WebSocket, лимит размера и типа фото.
- Ошибки Gemini не роняют сервер: есть запасная модель и офлайн-режим.
- Дисклеймер «справочная информация» в каждом ответе и вердикте.

### Как бот понимает обычные формулировки
Перед поиском Gemini «переводит» рассказ гражданина на язык базы (`services.understand`): 4–8 поисковых фраз вперемешку
бытовых и юридических («угрожают в игре» → «угроза», «травля в интернете»), срочность, признак несовершеннолетнего и до двух
уточняющих вопросов (возраст? требуют деньги?). Поиск идёт и по исходному тексту, и по этим фразам. Прямые запросы вида
«статья 33» ищутся по номеру (`rag.by_article`). Если Gemini недоступен, работает поиск по словарю `tools/keywords_ru.json`
и по `keywords` в самих файлах базы.

### Два вида источников: нормы и памятки
В `knowledge/` лежат документы двух видов (поле `kind` в шапке файла):
- `kind: norm` — дословный текст Конституции или закона. Только по ним бот говорит «закон гарантирует / запрещает».
- `kind: guide` — практическая памятка проекта (`guide_*.md`): что сохранить, куда пожаловаться, куда звонить. Это совет, не норма
  права, в интерфейсе помечается отдельно. В выдаче нормы идут первыми, затем до двух памяток. Жалоба и суд-тренажёр опираются
  **только на нормы**.
Памятки сейчас `verified: false`: прочитайте их и поставьте `true`, когда проверите (например, через юриста вуза).

### Срочная помощь (детерминированно, не от модели)
Если в вопросе угроза, насилие, шантаж или травля, ответ получает поля `safety` (текст), `urgency: "high"` и `help_lines`
(кнопки «позвонить»: 112, 102 и, при детях или травле, 111). Номера лежат в `services.HELP_LINES`.
Проверено по открытым источникам: 111 «Аманат» — единый телефон доверия по семье, женщинам и защите прав детей, бесплатно и круглосуточно.

## База знаний: Конституция РК 2026
В `backend/knowledge/` лежат **96 статей + преамбула** новой Конституции (принята на референдуме 15.03.2026,
действует с 01.07.2026), по одному файлу на статью; длинные статьи делятся на части по пунктам.
Текст взят из файла системы «ПАРАГРАФ» (prg.kz), структура проверена: 11 разделов, 96 статей, без пропусков
(это проверяет автотест). Старые демо-заготовки перенесены в `backend/knowledge_demo_archive/` и не загружаются.

Перезагрузка или обновление текста:
```bash
extract-text Конституция.docx > const.txt        # или: pandoc Конституция.docx -t plain -o const.txt
python tools/import_constitution.py const.txt --lang ru --url <официальная ссылка>
python tools/import_constitution.py const_kk.txt --lang kk   # казахская версия (формат «Бап N / Бөлім» не проверен на реальном файле)
```
Бытовые слова («справка», «уволили», «акимат») связаны со статьями в `tools/keywords_ru.json`: Конституция
написана общим языком, поэтому без этого поиск по обычным вопросам не работает. Словарь можно дополнять.

## Что нужно сделать до защиты
1. В `url` у статей сейчас ссылка на prg.kz (коммерческая база). Если найдёте официальную публикацию, перезапустите импорт с `--url`.
2. Импортировать казахский текст Конституции (команда выше) и проверить поиск на казахских вопросах.
3. Вписать `GEMINI_API_KEY` и точный код модели в `GEMINI_MODEL`.
4. Помнить границы: на вопросы, где нет ни нормы, ни памятки (штрафы ПДД, конкретные сроки), бот честно отвечает
   «в базе нет подтверждения». Это ожидаемое поведение. Чтобы бытовые вопросы получали ответ со статьями, а не только
   с памятками, загрузите нужные статьи кодексов: `python tools/import_law.py` (инструкция внутри файла).
   Начать стоит с УК РК: ст. 105 («доведение до самоубийства, склонение…») и ст. 115 («Угроза»), эти номера подтверждаются
   открытыми источниками. Остальные номера (вымогательство, мошенничество, трудовые нормы) найдите и сверьте сами.
5. Заменить рисунок барса на финальный (`Mascot.jsx`) и прочитать код: по пп. 6.6–6.7 его нужно уметь объяснить.

## Безопасность и данные (кратко для жюри, п. 13.1 положения)
- Секреты только в `.env` (в git не попадают). При `DEBUG=0` без `SECRET_KEY` сервер не запускается.
- Авторизация по токену `Authorization: Bearer`, cookie не используются, поэтому `@csrf_exempt` на API безопасен.
- Лимит запросов по IP, ограничение длины текста, защита от инъекций в промптах (в том числе в истории диалога),
  загрузка файлов проверяется по типу и «магическим байтам», размер ограничен.
- Источники в ответах берутся из базы, а не из текста модели; без источника бот отказывает.
- Тексты вопросов не логируются. Необязательный журнал пробелов (`LOG_GAPS=1`) пишет только вопросы с отказом, без номеров, e-mail и телефонов.
- Аккаунт и чаты можно удалить из интерфейса (`DELETE /api/auth/me/`).
